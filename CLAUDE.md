# Vocal Trainer

Singing practice app for the user (Windows 11, Edge). Plain HTML/JS, no framework or npm dependencies.

This is the user's public hobby project. Keep personal details out of the repo: no names, home paths, or emails in files, comments, or commit messages.

- Edit `src/`. `dist/` is build output and is not committed: `python3 build.py` builds it (single-file page, PWA files, and `vocal-trainer-windows.zip`), and CI builds it again on every push. If the icon changes, run `node scripts/render_icons.js` to re-render the PNGs in `src/pwa/` and commit them.
- Tests: `node test/core.test.js`, `node test/csv.test.js`, and `NODE_PATH=$(npm root -g) node test/e2e.test.js` (Playwright with a fake mic singing A3; uses /opt/pw-browsers chromium).
- Stored data shapes (localStorage keys `vt.sessions`, `vt.ranges`, `vt.minutes`, `vt.done`) must stay round-trippable through `src/csv.js`. If you add a field, add it to `exportTables`/`importTables` and the round-trip test.
- Delivery: push to `main` on github.com/carltonbonks/vocal-trainer; `.github/workflows/pages.yml` runs the unit tests, builds and publishes `dist/` to GitHub Pages, and the installed Edge app picks up the new version on its next launch (service worker cache name changes with each build). The user runs the app installed from the Pages site, with their CSV history in a data folder on their PC that the app is connected to. The Windows zip (`dist/vocal-trainer-windows.zip`) is still built for others but doesn't auto-update.
- **GitHub is the source of truth.** The history was rewritten on 2026-10-04 to remove personal details and a copyrighted song, so never push from a copy made before then. A claude.ai project working copy (at `/mnt/project-files/singing-trainer`) must be a clone of GitHub: pull before working, push to GitHub after committing.
- The shared folder adds content-credential metadata to images and audio when they are written, so `git status` there shows icons and `test/a3.wav` as modified. That is expected; commit from a clean clone rather than committing those changes.
- Songs live in `src/songs.js` as one line per bar ("start+note/length" in sixteenths, tied notes as one long note). **The repo is public: only public-domain melodies (or the user's own) go in it, never a transcription of a copyrighted song.** The user's sheet music stays out of git. `test/core.test.js` checks the song for bar overlaps and range; add a test like it for each new song. Never put lyrics in the repo or the app. Song runs are saved as sessions with mode `song`, one round per line, and the pattern field "title | part | key | bpm".
